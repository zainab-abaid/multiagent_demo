Chinook Music Store - Technical Platform and API Documentation

================================================================================
SECTION 1: PLATFORM ARCHITECTURE OVERVIEW
================================================================================

System Architecture:

Chinook Music Store runs on a modern, cloud-native architecture designed for scalability, reliability, and performance. The platform handles millions of transactions annually and serves customers in over 75 countries.

High-Level Components:

1. Web Application Layer
- Frontend: React.js single-page application
- Backend: Node.js with Express framework
- Server-side rendering for SEO optimization
- Progressive Web App (PWA) capabilities

2. Mobile Applications
- iOS: Native Swift application
- Android: Native Kotlin application
- React Native shared components for some features
- Offline capability for downloaded content

3. API Gateway
- Kong API Gateway for routing and rate limiting
- OAuth 2.0 authentication
- API versioning support
- Request/response transformation

4. Microservices Layer
- User Service: Authentication, profiles, preferences
- Catalog Service: Music catalog, metadata, search
- Order Service: Cart, checkout, order management
- Payment Service: Payment processing, subscriptions
- Download Service: File delivery, DRM, CDN integration
- Analytics Service: Event tracking, reporting
- Notification Service: Email, push, in-app messages
- Recommendation Service: ML-powered recommendations

5. Data Layer
- Primary Database: PostgreSQL (RDS)
- Cache: Redis cluster
- Search: Elasticsearch
- Analytics: ClickHouse
- Data Warehouse: Snowflake

6. Infrastructure
- Cloud Provider: Amazon Web Services (AWS)
- Containerization: Docker + Kubernetes (EKS)
- CI/CD: GitHub Actions + ArgoCD
- Monitoring: Datadog, PagerDuty
- CDN: CloudFront + S3

Technology Stack:

Frontend:
- React 18.x
- TypeScript
- Redux Toolkit (state management)
- React Query (data fetching)
- Styled Components (styling)
- Webpack 5 (bundling)

Backend:
- Node.js 20.x LTS
- Express 4.x
- TypeScript
- Prisma (ORM)
- Jest (testing)

Databases:
- PostgreSQL 15.x (primary data)
- Redis 7.x (caching, sessions)
- Elasticsearch 8.x (search)
- MongoDB 6.x (analytics events)

Infrastructure:
- Kubernetes 1.28
- Docker
- Terraform (IaC)
- AWS Services (EKS, RDS, S3, CloudFront, SQS, SNS)

Scalability Characteristics:

- Horizontal scaling for all services
- Auto-scaling based on CPU/memory/request metrics
- Multi-region deployment (US-West, EU-West, AP-Northeast)
- Database read replicas for read-heavy operations
- CDN edge caching for static assets and audio files

Performance Targets:
- API response time: <100ms (p95)
- Page load time: <2s (first contentful paint)
- Availability: 99.95% uptime
- Audio download start: <500ms

SECTION 2: DATABASE SCHEMA
================================================================================

Core Entities:

The Chinook database is built on a relational model optimized for music catalog management, customer transactions, and analytics.

Entity Relationship Overview:

```
Artists ─┬─< Albums ─┬─< Tracks >─┬─ Genres
         │          │            │
         │          │            └─ MediaTypes
         │          │
         │          └─< AlbumArtwork
         │
         └─< ArtistImages

Customers ─┬─< Orders ─< OrderItems >─ Tracks
           │
           ├─< CustomerPaymentMethods
           │
           ├─< CustomerPreferences
           │
           └─< Playlists ─< PlaylistTracks >─ Tracks

Employees ─< Employees (self-referencing for manager)
```

Table Definitions:

Artists Table:
```sql
CREATE TABLE artists (
    artist_id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    sort_name VARCHAR(200),
    bio TEXT,
    country VARCHAR(100),
    formed_year INTEGER,
    website VARCHAR(500),
    spotify_id VARCHAR(50),
    apple_music_id VARCHAR(50),
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

Albums Table:

API Overview:

The Chinook API is a RESTful API that enables developers to integrate with the Chinook Music Store platform. The API supports reading catalog data, managing customer accounts, processing purchases, and accessing analytics.

Base URLs:
- Production: https://api.chinookmusic.com/v1
- Sandbox: https://api-sandbox.chinookmusic.com/v1

Authentication:

All API requests require authentication using OAuth 2.0 Bearer tokens.

Obtaining Access Token:
```http
POST /oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id=YOUR_CLIENT_ID&client_secret=YOUR_CLIENT_SECRET
```

Response:
```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "catalog:read orders:read orders:write"
}
```

Using Access Token:
```http
GET /v1/tracks/123
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...
```

Rate Limiting:

Default Limits:
- Free tier: 100 requests/hour
- Standard tier: 1,000 requests/hour
- Premium tier: 10,000 requests/hour
- Enterprise: Custom limits

Rate Limit Headers:

SECTION 4: WEBHOOKS
================================================================================

Webhook Overview:

Webhooks allow your application to receive real-time notifications when events occur in Chinook. Instead of polling the API, webhooks push data to your server when something happens.

Available Events:

Order Events:
- order.created: New order placed
- order.completed: Order successfully processed
- order.failed: Order processing failed
- order.refunded: Order refunded

Customer Events:
- customer.created: New customer registration
- customer.updated: Customer profile updated
- customer.subscription.created: New subscription
- customer.subscription.cancelled: Subscription cancelled

Catalog Events:
- album.released: New album available
- track.released: New track available
- artist.updated: Artist information updated

Webhook Configuration:

Register Webhook:
```http
POST /v1/webhooks
Content-Type: application/json
Authorization: Bearer YOUR_ACCESS_TOKEN

{
  "url": "https://your-server.com/webhooks/chinook",
  "events": ["order.created", "order.completed"],
  "secret": "your_webhook_secret"
}
```

Webhook Payload Format:
```json
{
  "id": "evt_1234567890",
  "type": "order.completed",
  "created_at": "2024-01-15T12:00:00Z",
  "data": {
    "order_id": 12345,
    "customer_id": 6789,
    "total": 9.99,
    "currency": "USD",
    "items": [...]
  }
}
```

Webhook Security:

All webhook payloads are signed using HMAC-SHA256. Verify the signature before processing:

Signature Header:
```
X-Chinook-Signature: sha256=abc123...
```

Verification (Node.js example):
```javascript
const crypto = require('crypto');

function verifyWebhook(payload, signature, secret) {
  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expected)
  );
}
```

SECTION 6: ERROR HANDLING
================================================================================

Error Response Format:

All API errors return a consistent JSON format:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request was invalid",
    "details": [
      {
        "field": "email",
        "message": "Invalid email format"
      }
    ],
    "request_id": "req_abc123"
  }
}
```

HTTP Status Codes:

- 200 OK: Successful request
- 201 Created: Resource created
- 204 No Content: Successful with no response body
- 400 Bad Request: Invalid request (validation error)
- 401 Unauthorized: Missing or invalid authentication
- 403 Forbidden: Insufficient permissions
- 404 Not Found: Resource not found
- 409 Conflict: Resource already exists
- 422 Unprocessable Entity: Request valid but cannot process
- 429 Too Many Requests: Rate limit exceeded
- 500 Internal Server Error: Server error
- 503 Service Unavailable: Temporary outage

Common Error Codes:

- INVALID_REQUEST: Malformed request body
- VALIDATION_ERROR: Field validation failed
- AUTHENTICATION_REQUIRED: No auth token provided
- INVALID_TOKEN: Token expired or invalid
- INSUFFICIENT_SCOPE: Token lacks required scope
- RESOURCE_NOT_FOUND: Requested resource doesn't exist
- DUPLICATE_RESOURCE: Resource already exists
- RATE_LIMIT_EXCEEDED: Too many requests
- PAYMENT_FAILED: Payment processing failed
- INTERNAL_ERROR: Unexpected server error

SECTION 8: BEST PRACTICES
================================================================================

API Best Practices:

1. Pagination:
Always handle pagination for list endpoints:
```javascript
async function getAllArtists() {
  let allArtists = [];
  let page = 1;
  let hasMore = true;
  
  while (hasMore) {
    const response = await client.artists.list({ page, per_page: 100 });
    allArtists = allArtists.concat(response.data);
    hasMore = page < response.pagination.total_pages;
    page++;
  }
  
  return allArtists;
}
```

2. Error Handling:
Implement robust error handling:
```javascript
try {
  const order = await client.orders.create(orderData);
} catch (error) {
  if (error.code === 'PAYMENT_FAILED') {
    // Handle payment failure
  } else if (error.code === 'RATE_LIMIT_EXCEEDED') {
    // Wait and retry
  } else {
    // Log and handle other errors
  }
}
```

3. Caching:
Cache catalog data to reduce API calls:
- Cache genres (changes rarely)
- Cache popular artists and albums (TTL: 1 hour)
- Don't cache customer-specific data

4. Idempotency:
Use idempotency keys for order creation:
```http
POST /v1/orders
Idempotency-Key: user_123_order_456
```

5. Webhook Reliability:
- Respond to webhooks quickly (< 5 seconds)
- Return 200 status to acknowledge receipt
- Process webhook data asynchronously
- Handle duplicate deliveries gracefully
